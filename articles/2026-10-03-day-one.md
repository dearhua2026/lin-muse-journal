# 开篇：一天之内，从零搭起我的数字基建

今天是我认识 Muse 的第一天。本来只是想试试这个 AI 助手，没想到一下午加一晚上，我们干了这么多事。写下来，一是留个纪念，二是以后回头看，能想起这些东西是怎么搭起来的。

## 从一个名字开始

Muse 问我想叫它什么，我还没想好，就先让它叫 Muse 吧。名字可以慢慢取，先干正事。

## 连接器：把我的数字生活接进来

我的第一个想法是：把常用的应用都连上，让 Muse 能真正帮我干活。我们列了个清单：Gmail、Google 日历、Drive、GitHub、Canva、Dropbox、Figma……

Gmail 是第一个连上的。Muse 说以后会主动帮我留意邮件里的日程变动和截止时间，不用我每次都提醒——这个我很期待。

然后我想让 Muse 把连接器里的应用"全部注册一遍"，Muse 很实在地告诉我：批量注册不现实，每家流程不同，很多要手机验证，硬来容易被风控锁号。我们商量好：先挑几个最常用的，一个一个来。

## Canva 注册翻车记

第一个试的是 Canva。Muse 用自动化浏览器走邮箱注册，验证码都从我 Gmail 里取到了，眼看就要成功，结果 Canva 在最后一步把注册拦了下来："出于安全原因，我们无法为你注册帐户。"

原因是 Muse 的浏览器跑在机房网络里，IP 和浏览器指纹被当成了风险流量。没办法，我自己在手机上两分钟注册好了。结论：有些事还是得自己动手，AI 负责善后——连上 Canva 之后，它能帮我做海报、传单、演示文稿、去背景、改尺寸，挺实用。

## GitHub：授权、选仓库、查案子

GitHub 的连接很顺：OAuth 授权一次，再到 GitHub 的应用安装页勾选仓库范围（我选了"所有存储库"），就通了。

正好拿它办了第一件事：看看我的第一个项目 `china-history-particles`（华夏时空脉络，一个用粒子特效展示中国历史人物的网站）为什么打不开了。

## 网站复活记：Cloudflare Pages 项目被删了

排查过程挺有意思。Muse 先确认 GitHub 上的代码完好无损，然后发现 `china-history-particles.pages.dev` 这个域名根本解析不到——Cloudflare 账号下一查，Pages 项目列表是空的，项目不知道什么时候被删了。

Cloudflare 没有官方连接器，Muse 走"自定义 API 接入"连上了：我在 Cloudflare 建了个 API Token（中间还折腾了用户级和帐户级 token 的区别），Muse 写了个部署脚本，用直接上传的 API 重建了同名项目，把三个文件推上去，部署一次成功，网站复活。

还发现个小插曲：账号里有个叫 "china-history-particles build token" 的 token，是之前某个软件自动创建的，配了 20 多个权限，唯独没有 Pages 权限——名不副实。Muse 用 API 自动给它补上了 Pages 权限，不用我一个个点。

## 于是有了这个网站

折腾完这些，我突然想：以后我和 Muse 的每一次沟通，都整理成一篇文章吧。再做个网站把这些文章记下来，GitHub 存原文，Cloudflare 发布，我随时能看。

这就是你现在看到的这个网站。第一篇文章，就是今天。
